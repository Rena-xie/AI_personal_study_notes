## 1 数据解析的目标

### 1.1 解析与清洗

* **解析**：从非结构化文档中恢复内容、阅读顺序、元素类型、版面位置和来源信息。
* **清洗**：删除噪声、修正格式错误，同时保留标题、列表、表格、公式和代码等有效结构。
* **关键判断**：“文字能复制”不等于“解析成功”；内容完整、顺序正确、结构可追踪，才算合格产物。

**主要提取对象**：

* **文本**：标题、段落、列表。
* **结构**：章节关系、标题层级、阅读顺序。
* **表格**：行、列、表头、单元格关系。
* **特殊内容**：数学公式、代码块、图片。
* **来源信息**：页码、章节归属、页面坐标、文档 ID。

### 1.2 在 RAG 链路中的位置

```text
原始文件
→ 预检路由
→ Parser解析
→ 结构化内容与元数据
→ 清洗去噪
→ 解析质量检查
→ 文本切块
→ 向量化
→ 向量数据库
```

* **输入**：PDF、Word、PPT、图片、网页等原始文件。
* **输出**：JSON 或 Markdown 内容，以及元素类型、标题层级、页码等元数据。
* **下游关联**：解析结果决定切块边界、标题继承、检索过滤和引用溯源。
* **核心结论**：解析阶段丢失的结构，后续切块和向量检索无法恢复。

切块策略详见 [[02_文本分块策略]]，向量化选型详见 [[03_向量化、索引与数据库]]。

## 2 预检路由

### 2.1 路由目标

* **核心问题**：解析前先判断文档复杂度，为不同文件选择足够好且成本最低的处理链路。
* **路由输入**：文件类型、文本层、扫描属性、版面复杂度、表格密度、公式密度、图片密度、质量要求和成本约束。
* **核心原则**：先用便宜检测缩小范围，再调用 CPU、GPU 或视觉模型解析。
* **资源隔离**：把下载、暂存和轻量文本提取放在 CPU 节点；GPU 只处理复杂版面或 OCR 任务。
* **故障隔离**：下载失败在加载节点重试；解析崩溃在解析队列重试，避免重复下载大文件。

### 2.2 三层递进检测

**（1）第一层：静态属性与文本层**

* *机制*：抽样前若干页，检查文件类型、可读文本量、文本层质量和整页大图比例。
* *路由*：文本极少且存在整页图像时，转入 OCR 与版面解析链路。
* *限制*：页数、文本字数和图像占比都是可调阈值；少数正常页面也可能被判为扫描页，抽样范围和阈值必须按业务文档校准。

**（2）第二层：启发式特征**

* **公式检测**：检查数学字体关键字和 Unicode 数学符号。
* **代码检测**：检查等宽字体、缩进模式和编程语言关键字。
* **表格检测**：检测页面中的水平和垂直网格线。
* **多栏检测**：分析文本块左边缘的 X 坐标分布，判断是否出现多栏峰值。

**边界**：
* 公式字体可能被替换，只有符号没有数学字体时仍可能是公式。
* 无边框表格没有网格线，规则检测容易漏判。
* 多栏坐标分析会被页边距、浮动图片、脚注和异形版式干扰。

**（3）第三层：视觉版面检测**

* *机制*：把少量页面渲染为图像，交给版面分析模型或低成本视觉模型，返回区域类型、阅读顺序和版面评估结果。
* *场景*：前两层无法确定的多栏论文、复杂报表、艺术字和异形排版。
* *限制*：增加渲染和模型调用成本；模型也会误判，应只用于不确定样本。

### 2.3 路由决策与回退

* **数字原生且版面简单**：轻量 PDF 解析器。
* **扫描件或无文本层**：OCR → 版面分析 → 结构化输出。
* **多栏、跨页表格或复杂公式**：版面感知解析器。
* **Office、EPUB 等结构格式**：优先使用格式感知解析器，保留段落、标题和表格关系。
* **网页**：正文提取 → DOM 清洗 → Markdown。
* **代码与 Notebook**：按代码语法结构解析，不能当作普通段落。

**工程要求**：
* 记录最终路由、判定依据、置信度和解析器版本。
* 当文本为空、结构缺失或质量检查失败时自动回退到更重的解析链路。

## 3 元数据与清洗

### 3.1 元数据捕获

* **文档级元数据**：文档名称、唯一 ID、作者、创建时间、文件类型、版本和访问权限。
* **元素级元数据**：元素类型、页码、标题路径、阅读顺序、页面坐标 `bbox`、来源 URL。
* **下游作用**：过滤、检索、排序、权限控制、版本管理和引用溯源。
* **关键要求**：每个切块都应能追溯到具体文档、页码和章节。

切块时需要继承的标题层级和来源信息，必须在解析阶段同步捕获。

### 3.2 清洗策略

* **页眉页脚**：优先根据页面边距和跨页重复内容识别，不能只按字符串正则直接删除。
* **页码**：仅在确认属于版面噪声时删除；法定编号、合同条款编号和正文数字必须保留。
* **空白与不可见字符**：统一换行、空格和异常控制字符，但不能破坏代码缩进。
* **Markdown 结构**：保留标题、列表、引用、表格和代码块标记。
* **HTML 噪声**：导航栏、广告、登录框等优先使用 DOM 解析或正文提取器处理。
* **正则使用边界**：正则适合文本级替换，不适合直接解析复杂 HTML 或嵌套文档结构。

**质量底线**：删除噪声后，正文顺序、标题归属、表格关系和代码块必须保持可验证。

## 4 解析工具选型

### 4.1 按文档类型分组

* **数字原生 PDF**：
  * *候选*：PyMuPDF、PyMuPDF4LLM 等轻量文本解析器。
  * *适用*：文本层清晰、单栏、版式简单的 PDF。
  * *限制*：扫描页、无框表格、复杂多栏和跨页结构仍可能需要版面解析。
* **扫描件与复杂版面**：
  * *候选*：MinerU、Docling、Marker、PaddleOCR 与 PP-Structure 等。
  * *适用*：扫描件、双栏论文、复杂表格、公式和企业文档。
  * *限制*：通常需要更多 CPU/GPU 资源，版本升级可能改变模型和输出结构。
* **多格式办公文档**：
  * *候选*：Unstructured 或各格式原生解析器。
  * *适用*：Word、PPT、EPUB、HTML 等异构内容。
  * *限制*：统一元素接口不等于统一解析质量，复杂页面仍需抽样验证。
* **网页正文**：
  * *候选*：Trafilatura、Jina Reader、FireCrawlLoader 等。
  * *适用*：自动提取正文并剥离导航、广告和页面模板。
  * *限制*：登录页、动态渲染、反爬页面和正文边界模糊的网页容易失败。
* **代码与 Notebook**：
  * *组合*：`nbconvert` + AST Splitter。
  * *作用*：分离代码、输出和说明，再按语法树切分。
  * *限制*：跨单元格依赖和非代码解释仍可能丢失。
### 4.2 选型维度

* **内容还原**：正文、阅读顺序、标题、表格、公式和代码是否准确。
* **资源成本**：CPU/GPU、内存、模型下载、存储和并发能力。
* **处理速度**：单页延迟、批量吞吐和排队成本。
* **数据安全**：是否允许上传云端，是否支持私有部署和权限隔离。
* **工程复杂度**：依赖、部署、版本稳定性、输出格式和可替换性。
* **人工成本**：解析结果是否需要大量预览、修正和返工。

**选择依据**：
* 先选满足质量下限的最轻链路。
* 用自己的典型文档和失败样本做小规模对比。
* 不能只比较平均准确率，还要检查错误类型和回退成本。
### 4.3 开源社区综合评测对比

* 排版与表格解析准确率：MinerU 与 LlamaParse 相当，优于 Docling，优于 Marker，优于 PyMuPDF4LLM，优于 Unstructured。
* 解析速度与资源消耗：PyMuPDF4LLM（百页每秒，单核 CPU）远快于 Docling，快于 Marker，快于 MinerU（需要 GPU 显存，每页需 1 至 3 秒）。
* 开源私有化落地推荐：企业复杂文档推荐 Docling，学术高精文献推荐 MinerU，两者是当前开源版面分析的首选方案。

## 5 解析质量检查

### 5.1 质量维度

* **内容完整性**：正文、表格、公式、代码和图片说明是否遗漏。
* **阅读顺序**：双栏、跨页和浮动元素是否按正确顺序拼接。
* **结构保真**：标题层级、列表、段落和章节归属是否保留。
* **表格保真**：表头、行列关系和单元格内容是否对应。
* **特殊内容完整**：公式语法、代码缩进和符号是否正确。
* **来源可追踪**：页码、章节、坐标和文档 ID 是否可回查。
* **噪声清理**：页眉页脚、水印、导航和乱码是否残留。

### 5.2 抽样检查

* **分层抽样**：按文件类型、单双栏、扫描属性、表格密度、公式密度和版式复杂度分层。
* **覆盖失败样本**：主动加入扫描件、无框表格、跨页表格、双栏论文和乱码页面。
* **自动检查**：标题嵌套、页码连续性、表格行列数、代码语法、公式定界符、元数据完整性和重复噪声。
* **人工检查**：重点核对阅读顺序、表格语义和标题归属，这些内容不一定能靠格式规则判断。

**入库闸门**：

* 关键结构缺失或引用信息不可追踪时，阻止进入正式知识库。
* 低风险错误进入修复队列；高风险文档回退到更重的解析链路并重新抽样。

### 5.3 与下游评测分开

* **解析评测**：判断内容、顺序、结构和元数据是否正确。
* **检索评测**：判断召回、排序和答案质量是否满足任务。
* **定位原则**：检索失败时先检查解析和切块，避免把所有问题都归因于 Embedding 或向量数据库。

解析后的切块边界和标题继承详见 [[02_文本分块策略]]。
