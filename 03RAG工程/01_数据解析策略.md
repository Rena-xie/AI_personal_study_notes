解析的本质是从复杂的非结构化文档中恢复内容、顺序与结构，将其还原为机器能够理解、处理与追踪的结构化数据。数据解析提取的主要内容类型包括：
* 文本：标题、段落、列表。
* 结构：章节、标题层级。
* 表格：行、列、表头、单元格数据。
* 特殊内容：数学公式、代码块、图片。
* 来源信息：页码、章节归属、文档唯一标识。

* **解析**：识别并恢复文档中的内容、结构、顺序、元素类型、空间位置等元信息。
* **清洗**：删除或修正不希望进入知识库的噪声、格式错误以及冗余内容。
### 1.2 整体解析与处理管道

在完整的 RAG 接入流水线中，原始非结构化文件从接收到最终存入向量数据库，经历以下标准化处理流程：

```text
            原始文件
    (PDF / Word / PPT / 图片)
                │
                ▼
           预检路由 Router
                │
                ▼
       文档处理工具集群 Parser
   (Docling / MinerU / Marker等)
                │
    ┌───────────┼───────────┐
    ▼           ▼           ▼
   文字        表格        图片
    │           │           │
    └───────────┼───────────┘
                ▼
           结构化文档
        (JSON / Markdown)
                │
                ▼
           正则清洗去噪
                │
                ▼
           解析抽样检查
                │
                ▼
         文本切块 Chunking
                │
                ▼
         向量化 Embedding
                │
                ▼
        向量数据库 Vector DB
```

### 1.3 在 RAG 链路中的定位与作用

* 输入：原始文件（包含 PDF、Word、PPT、图片、网页等）。
* 输出：结构化文档（JSON 或 Markdown 格式）以及对应的元素类型与元数据。
* 下游关联：解析产物直接决定了后续文本切块的边界位置、可继承的标题层级，以及用于精准过滤的元数据条件。切块策略详见 [[02_文本分块策略]]，向量化选型详见 [[03_向量化、索引构建及数据库]]。

## 2 预检路由机制

### 2.1 预检路由

通过预检路由实现按需分配算力，能够在解析精度、处理速度与计算成本之间取得平衡。这种解耦设计带来了三大工程优势：

* 资源精准隔离：文件加载器运行在低成本的 CPU 容器中，高并发拉取和暂存网络文件；解析器部署在配置 GPU 加速的微服务集群中（运行 MinerU、PaddleOCR、Docling 等），避免轻量级下载与传输任务占用昂贵的 GPU 显存。
* 细粒度容错与重试：网络波动或下载失败仅需在加载节点重试；若某类复杂文档导致解析器内存溢出或崩溃，只需对解析队列重试，无需重新下载大文件。
* 组合路由：加载节点统一吐出标准字节流，中间路由层根据预检结果进行分流，将简单纯文本路由给 CPU 上的 PyMuPDF，将复杂双栏论文路由给 GPU 上的 MinerU，实现全系统资源消耗最小化。

### 2.2 三层递进式预检检测策略

路由决策时综合考量文件类型、是否有文本层、是否为扫描件、版面复杂程度、表格密度、公式密度、图片密度、质量要求以及成本与速度要求。预检路由采用由轻到重的三层递进检测架构：

```text
文档输入 ──> 第一层：静态元信息检测 ──> 第二层：启发式特征分析 ──> 第三层：视觉模型检测 (按需) ──> 决策路由输出
```

**（1）第一层：静态属性与基础检测**

利用轻量工具（如 PyMuPDF/fitz）抽样文档的前 3 页。如果单页提取出的可读文本字数极少（如小于 50 字），且页面内存在覆盖全页的大图，则直接判定为扫描件，强制路由至 OCR 与视觉解析管道。

**（2）第二层：启发式特征采样分析**

* 数学公式检测：检查嵌入字体列表中是否包含 Math、CMEX、CMSY、TeX、Cambria Math 等关键字，或检测文本流中是否高频出现 Unicode 数学符号。
* 代码块检测：检测文本是否使用了等宽字体（如 Courier、Consolas、Monaco），并配合正则表达式检测常规缩进与编程语言关键字。
* 表格检测：调用 PyMuPDF 的表格查找功能，检测页面中是否存在互相交错的矢量水平线和垂直线构成的网格。
* 多栏与双栏排版：分析页面所有文本块左边缘 X 坐标的直方图。若坐标分布呈现明显的双峰特征，说明该文档为双栏排版的学术论文或报刊，需路由至支持版面重构的解析器。

 **（3）第三层：轻量级 AI 与视觉检测**

* 适用场景：前两层启发式规则无法确定的异形文档、复杂排版报表或艺术字排版。
* 检测手段：将文档前 1 至 2 页渲染为低分辨率图像，输入至轻量版面分析模型（如 YOLOv8-Layout、PP-Structure）或低成本视觉大模型（如 Qwen2-VL-7B、GPT-4o-mini），返回结构化的 JSON 版面评估结果。

## 3 上下文元数据捕获与文本去噪

### 3.1 物理与结构元数据捕获

解析器在提取文本内容的同时同步捕获元数据。元数据不仅用于显示来源，还参与后续的过滤、检索、排序、权限控制和版本管理，是实现带过滤条件的混合检索以及精准引用溯源的基础。

捕获的元数据分为两类：

* 文档级别元数据：文档名称、唯一标识 ID、作者、创建时间、文件类型、安全涉密等级。
* 位置与结构元数据：绝对页码、章节归属、标题层级深度、元素在页面的坐标框。

### 3.2 文本正则清洗与去噪

在将结构化元素送入切块逻辑之前，必须剔除文本中的无意义杂质。在压缩空白、剥离杂质的同时，必须保留 Markdown 标题、列表、表格与代码块的结构。通过编写正则表达式完成以下清理工作：

* 剔除页眉页脚与版权声明。
* 独立页码清理：清理混在正文段落中间的独立数字页码。
* 格式杂质清理：剥离无用的 HTML 标签、垃圾链接、不规范的不可见字符，并将 3 个以上连续换行符归一化为 2 个换行符。
* 网页噪声过滤：自动剥离导航栏、登录按钮、相关推荐、广告、评论区、Cookie 提示、分享按钮以及版权信息等网页杂质。

## 4 解析工具选型矩阵与对比

### 4.1 主流解析工具特性

开源与商业社区提供了丰富的文档解析工具，各自适用于不同的算力条件与文档复杂度：

* PyMuPDF4LLM：轻量级 PDF 转 Markdown 工具，底层基于 C++ 实现，解析速度可达百页每秒（单核 CPU 运行），能够保留 Markdown 标题层级与代码块缩进，适合数字原生 PDF 的快速处理。
* TextLoader / DirectoryLoader：基础文本与目录加载器，零额外 CPU/GPU 开销，适合纯文本、Markdown 或 TXT 文件的快速接入。
* MinerU (Magic-PDF)：上海人工智能实验室开源，集成 LayoutLMv3、YOLOv8 与 UniMERNet 等深度模型，对学术论文、双栏排版、跨页表格与复杂数学公式的提取能力极强，需要 GPU 算力支持。
* Docling：IBM 开源的模块化版面分析工具，基于视觉大模型识别版面，表格与公式还原度高，适合企业私有化部署。
* Marker：基于 GPU 加速的高效 PDF 转 Markdown 工具，专注于科研文献与电子书解析，速度显著快于重型版面模型。
* Unstructured：支持 20 多种格式（包括 PDF、Word、PPT、EPUB、HTML）的通用开源库与 API 服务，提供统一的元素接口。本地运行高分辨率解析依赖 Poppler、Tesseract、OpenCV 等重型依赖，Docker 镜像庞大，处理耗时较长。
* LlamaParse：云端 API 商业解析服务，对复杂嵌套表格与多列混排解析精度极高，按页计费，需要评估数据上云的合规风险。
* Trafilatura / Jina Reader / FireCrawlLoader：专用于网页抓取，能够自动剥离 DOM 树导航栏、广告与页脚，输出洁净的 Markdown 内容。
* PaddleOCR：百度开源的轻量级中文 OCR 工具（包含 PP-Structure），具备高精度的扫描件文本与表格提取能力，支持 CPU 环境高效部署。
* RAGFlow：内置深度文档理解引擎 DeepDoc，提供可视化界面，支持用户对解析与切分结果进行实时预览、校验与手动调整。
* nbconvert 与代码切片器：通过 nbconvert 将 Jupyter Notebook 转换为纯净代码与文本，再按编程语言语法拆分。

### 4.2 业务场景选型矩阵

| **业务场景** | **优先推荐工具** | **选型理由与技术特点** |
| --- | --- | --- |
| 本地基础文本库冷启动 | TextLoader / DirectoryLoader | 秒级加载，零 CPU/GPU 开销，适合简单文本快速验证 |
| 标准数字版 PDF（单栏 / 图书） | PyMuPDF4LLM | 速度极快（百页/秒），单核 CPU 运行，完美保留标题层级与代码缩进 |
| 高效 PDF 转 Markdown（科研电子书） | Marker | 基于 GPU 优化，速度快于传统重型版面模型，Markdown 转换质量高 |
| 学术论文 / 双栏排版 / 复杂公式 | MinerU (Magic-PDF) | 集成 LayoutLMv3 与 UniMERNet，精准重构双栏阅读顺序与 LaTeX 公式 |
| 企业复杂合同 / 跨页表格（本地部署） | Docling (IBM) | 模块化版面识别，表格与跨行单元格还原度优异，支持私有化 |
| 商业级高精表格 / 嵌套版面（云端 API） | LlamaParse | 云端高精度解析，处理极复杂嵌套表格，按页付费 |
| 网页抓取 / 在线新闻与文档 | Trafilatura / Jina Reader | 自动剥离 DOM 树杂质、广告与导航，输出干净 Markdown |
| 多格式异构文档（Word/PPT/EPUB 等） | Unstructured | 统一元素接口，适配 20 多种文档格式的标准化提取 |
| 扫描件 / 截图 / 无文本层 PDF | PaddleOCR | 轻量级中文 OCR 与 PP-Structure 表格重建，支持 CPU 部署 |
| 端到端 RAG / 解析可视化微调 | RAGFlow | 提供可视化 UI，支持解析与切片结果的手动干预与校验 |
| 代码仓库与 Notebook | nbconvert + AST Splitter | 干净转换文件并按语法树拆分，保障代码逻辑完整性 |

### 4.3 开源社区综合评测对比

* 排版与表格解析准确率：MinerU 与 LlamaParse 相当，优于 Docling，优于 Marker，优于 PyMuPDF4LLM，优于 Unstructured。
* 解析速度与资源消耗：PyMuPDF4LLM（百页每秒，单核 CPU）远快于 Docling，快于 Marker，快于 MinerU（需要 GPU 显存，每页需 1 至 3 秒）。
* 开源私有化落地推荐：企业复杂文档推荐 Docling，学术高精文献推荐 MinerU，两者是当前开源版面分析的首选方案。

## 5 解析抽样检查

文档解析完成后，在存入向量数据库进行物理切片之前，必须建立自动化与人工结合的抽样检查机制，防止脏数据流入后续环节：

* 标题层次校验：检查文档导出的 Markdown 标题层级（一级、二级、三级标题）是否完整，防止标题遗漏或将正文大字误标为标题，导致层级切片失效。
* 公式与代码完整性校验：抽查数学公式和代码块是否在解析中发生语法折断、格式乱码或缩进丢失。
* 残留杂质清理校验：二次检查输出文本中是否仍残留页眉页脚、水印文字、无意义页码或乱码字符，确保向量数据库入库文本的纯净度。
