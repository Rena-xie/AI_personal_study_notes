## 1 检索前查询工程背景与核心机制

### 1.1 原始提问的缺陷与引入契机

用户原始提问通常存在以下五类天然缺陷：
* **表达口语化与语法不规范**：用户倾向于输入简短、含糊或充满口语套话的语句。
* **上下文与主语缺失**：在多轮对话中，用户提问往往包含大量的代词，脱离上下文直接检索会导致严重的检索偏离。
* **信息过于具体或过于抽象**：过于具体的问题容易缺乏通用的背景知识，过于抽象的问题则难以直接匹配具体的文档切片。
* **跨多实体复合提问**：单条提问中可能同时包含多个不同的实体和查询子需求。
* **语义空间错配**：用户使用的提问词汇（短文本、问题视角）与知识库文档（长文本、答案视角）在向量空间中存在内在的语义表达差异。

因此，必须在 Query → Retriever → Context → LLM 的链路中引入检索前智能查询处理层。其核心思想是将大语言模型从单纯的“文本生成器”升级为“意图解析器与规划器”，先精准理解用户真实意图，再将原始 Query 转化为最适合知识库检索的形式。

## 2 查询重构技术

### 2.1 查询重构六大技术

1. **查询重写**
   利用 LLM 将用户原始问题改写为语义更明确、更完整、更适合检索的 Query。典型处理包括语法纠错、补充省略信息、代词指代还原、多轮对话上下文融合、补充必要实体、消除歧义以及将口语化表达转换成更适合搜索的表达。目标是在保持原始用户意图的同时提高检索可用性。实践中可同时保留原 Query 并生成 Rewrite Query，避免改写错误导致信息损失。

2. **多查询**
   一个用户问题可能存在多个合理的表达方式。Multi-Query 使用 LLM 从不同角度生成多个 Query，然后分别检索，最后合并结果。

3. **查询扩展**
   给原始 Query 增加同义词、相关术语、关键词或其他检索表达，扩大 Query 与知识库词汇之间的覆盖范围。

4. **子问题拆解**
   针对包含多个独立意图或多个实体的复杂问题，将一个复杂问题拆解为多个逻辑上独立的子问题。

5. **退一步提示**
   先从具体问题退到更高层次、更一般的原理问题，再检索基础知识。适合以下场景：
   * 技术原理解释
   * 复杂专业问题
   * 需要基础理论支撑的推理问题
   * 法规/标准中的具体条款理解
   * 科学知识问答

6. **假设性文档嵌入**
   将“问题检索文档”转换为“假设性文档检索真实文档”，让查询表示更接近知识库中的文档表示，从而跨越语义鸿沟，提升高难度提问的召回效果。假设性文档由 LLM 生成，存在四类副作用：可能包含事实错误、添加原问题没有的信息、引入偏差以及增加一次 LLM 调用。因此 HyDE 不是必然提升召回率，而是一种需要通过检索评估验证的策略。

### 2.2 检索评估与验证指标

查询重构策略的效果不应凭感觉判定，而应通过以下指标进行定量验证：
* Recall@K
* Precision@K
* MRR
* NDCG
* Context Recall
* Context Precision
* Answer Correctness
* Faithfulness

## 3 查询构建与结构化筛选

### 3.1 元数据过滤提取

在现实业务中，知识库不仅包含非结构化文本，还附带丰富的结构化元数据（如创建时间、作者、部门分类、密级等）。传统的向量检索无法处理硬性过滤条件。利用 LLM 可将自然语言提问自动解析拆解为两部分：
* **语义检索词**：用于向量数据库的相似度搜索。
* **结构化过滤条件**：提取出表达式（如 year == 2024 AND category == 'technical'），在向量计算前强行过滤数据库元数据。

### 3.2 结构化数据查询扩展

* **Text2SQL**：针对关系型数据库，利用 LLM 理解数据库 Schema、表关联字段描述及少样本示例，将自然语言直接转换为标准 SQL 查询，并结合 SQL 执行器反馈进行自动报错重试。
* **Cypher 语句生成**：针对知识图谱（如 Neo4j），将自然语言转换为图查询语言，用于提取复杂实体拓扑关系。

## 4 智能查询路由

### 4.1 三大分发维度

* **数据源路由**：决定查询去往何种底层存储（如产品文档去向量库，用户订单去 SQL 数据库，股权关系去知识图谱，实时新闻去 Web 搜索引擎）。
* **组件与能力路由**：决定调用何种处理链（如简单 FAQ 走基础向量检索，复杂业务逻辑走 Agent 编排，自动化操作走 API Tool）。
* **提示词路由**：根据问题领域自动匹配专用的系统提示词（如代码问题路由至 Code Prompt，逻辑推理路由至 CoT Prompt）。

### 4.2 路由机制原理与对比

| 路由机制                 | 判断方式       | 响应延迟           | Token 成本 | 复杂意图处理能力      | 适用场景                |
| -------------------- | ---------- | -------------- | -------- | ------------- | ------------------- |
| **LLM Router**       | 大模型语义分类与规划 | 较慢 (100~300ms) | 有成本      | 极强，支持深层推理与多分支 | 复杂业务 Agent、多阶段任务调度  |
| **Embedding Router** | 向量空间余弦相似度  | 极快 (<10ms)     | 零成本      | 较弱，依赖表面语义匹配   | 高并发低延迟路由、领域明确的数据源分流 |
