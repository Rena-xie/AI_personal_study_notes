## 1 RAG 全局链路

### 1.1 离线知识构建

```text
原始文档
→ 01 数据解析：恢复内容、顺序、结构与来源信息
→ 02 文本分块：形成可检索的知识单元
→ 03 向量化与索引：
   ├── Dense：Chunk → Embedding → 向量索引 / 向量数据库
   └── Sparse：Chunk → 分词与统计 → 倒排索引
→ 可供在线检索的知识库
```

**核心产物**：
* 结构化正文与 Metadata。
* 带来源信息的 Chunk。
* 文本、向量、索引及文档版本。
### 1.2 在线检索生成

```text
用户 Query
→ 04 查询工程：重写、扩展、拆解、过滤条件提取、数据源路由
→ 05 混合检索：Dense + Sparse 并行召回
→ 得分融合 → Reranker 精排
→ 去重、扩展、压缩、Token 预算
→ LLM 基于 Context 生成
→ 引用溯源与质量评估
```

**核心约束**：
* 检索前尽量表达完整意图并选对数据源。
* 召回阶段优先保证相关证据进入候选集。
* 重排阶段提高相关证据的位置精度。
* 生成阶段必须受 Context 约束，并保留来源。
### 1.3 五篇笔记的职责

* [[01_数据解析策略]]
  * *输入*：PDF、Word、PPT、网页、图片等原始文件。
  * *输出*：结构化内容、阅读顺序、元素类型和来源 Metadata。
  * *核心问题*：内容是否完整、顺序是否正确、结构是否可追踪。
* [[02_文本分块策略]]
  * *输入*：结构化文档及标题层级。
  * *输出*：保留语义边界、章节归属和来源信息的 Chunk。
  * *核心问题*：块大小、边界、重叠和上下文完整性。
* [[03_向量化、索引与数据库]]
  * *输入*：Chunk 与 Metadata。
  * *输出*：Embedding、向量索引、检索记录和数据库结构。
  * *核心问题*：向量表示、相似度、召回效率、过滤与存储。
* [[04_查询工程]]
  * *输入*：用户原始 Query、对话上下文和可用数据源信息。
  * *输出*：检索用 Query、结构化过滤条件和路由决策。
  * *核心问题*：意图是否完整、改写是否失真、是否进入正确检索链路。
* [[05_检索与重排]]
  * *输入*：查询表示、过滤条件和候选知识库。
  * *输出*：混合召回候选、精排结果、构建后的 Context 和最终答案。
  * *核心问题*：候选是否召全、排序是否准确、上下文是否有效。
## 2 阶段接口与依赖

### 2.1 必须保持一致的接口
* **内容标识**：`document_id`、文档版本和来源位置从解析一直传递到答案引用。
* **章节信息**：标题路径由解析产生、切块继承、检索返回并进入生成上下文。
* **向量空间**：离线 Chunk 与在线 Query 必须使用兼容的 Embedding 模型和预处理。
* **过滤字段**：权限、租户、时间、文档类型等 Metadata 必须同时存在于索引与查询条件中。
* **数据版本**：正文、向量、索引和模型版本的更新要可协同，避免新旧记录混用。
### 2.2 故障传播关系
* 解析丢失内容 → 切块无内容可保留。
* 切块破坏语义 → Embedding 只能表示残缺片段。
* Embedding 或索引配置错误 → 正确 Chunk 无法被召回。
* Query 理解错误或路由错误 → 检索进入错误知识空间。
* 候选集漏掉正确证据 → Reranker 无法补救。
* Context 冗余或截断 → 生成层缺少证据或产生错误归纳。
## 3 端到端排障顺序

### 3.1 从数据到答案逐层定位

1. **解析**：目标内容、表格和章节是否已进入结构化产物？
2. **分块**：正确证据是否完整保留在单个或可扩展的 Chunk 中？
3. **索引**：对应 Chunk 是否已入库，模型版本、维度和过滤条件是否一致？
4. **查询**：改写后的 Query 是否保持原意，路由是否进入正确数据源？
5. **召回**：Dense 与 Sparse 候选集中是否出现正确证据？
6. **重排**：正确证据是否进入靠前位置，融合权重是否合理？
7. **上下文**：是否正确去重、扩展、压缩并控制 Token 预算？
8. **生成**：答案是否严格受 Context 支撑，引用是否可回查？

**判断原则**：
* 正确证据未入库：检查 01～03。
* 正确证据已入库但未召回：检查 Query、Embedding 一致性和索引过滤。
* 正确证据已召回但排名低：检查混合检索、融合与 Reranker。
* 正确证据已进入上下文但答案错误：检查 Prompt、生成约束和模型能力。
## 4 贯穿全链路的工程基线

### 4.1 统一观测数据
* 为每次请求记录原始 Query、改写 Query、路由、过滤条件、候选列表、重排得分和最终 Context。
* 为每个 Chunk 保留文档 ID、版本、页码、标题路径和权限标签。
* 记录解析器、Embedding、Reranker 和 LLM 的模型版本及关键参数。
### 4.2 分阶段评测
* **离线质量**：检查 01～03 的内容保真、切块完整性和入库一致性。
* **在线召回**：检查 04 的查询意图保持、路由准确性，以及 05 的召回与排序效果。
* **生成质量**：检查 Context 覆盖度、答案忠实度、引用可回查性和拒答质量。
* **评测边界**：各阶段指标独立记录，具体指标与测试方法进入对应笔记。
### 4.3 决策原则
* 没有分阶段评测，不增加复杂策略。
* 没有候选证据，不通过调 Prompt 补事实。
* 没有明确瓶颈，不同时调整切块、Embedding、过滤和重排参数。
* 优先使用满足质量下限的最简链路，再根据错误分布增加复杂度。
