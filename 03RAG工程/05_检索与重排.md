* **本层任务**：从知识库召回候选证据，融合、精排并构建生成上下文。
* **上游**：查询改写、过滤条件和路由见 [[04_查询工程]]；向量、索引与 Metadata 见 [[03_向量化、索引与数据库]]。
* **下游**：Context 和原始问题进入 LLM 生成答案。
* **核心目标**：候选召回得全、相关证据排得准、上下文装得有效、答案可以溯源。

## 1 双路混合检索与异构得分融合

### 1.1 稠密与稀疏检索互补

* **Dense Retrieval（稠密检索）**：
  * *优势*：理解语义、改写表达和跨语言相似性。
  * *局限*：对代码函数名、配置参数、产品型号、数字编号和未登录词容易漏召回。
  * *原因*：专有词被语义编码后，字面差异被压缩。
* **Sparse Retrieval（稀疏检索）**：
  * *优势*：直接匹配字面词项，适合专有名词、编号和精确短语。
  * *局限*：同义词、改写表达和跨语言能力弱。
  * *代表*：BM25。

**BM25 的三个组成部分**：
* **TF（词频）**：查询词在文档中出现越多，得分越高，但增长会饱和。
* **IDF（逆文档频率）**：词越稀有，区分度越强，权重越高。
* **文档长度归一化**：抑制长文档仅靠词数多获得优势。

**组合判断**：Dense 补语义，Sparse 补字面，两者并行形成互补召回。
### 1.2 双路检索流程

```text
Query
├── Dense Retrieval → Top-K Dense
└── Sparse Retrieval → Top-K Sparse
                 ↓
         Fusion（RRF / 加权）
                 ↓
          Candidate Set
                 ↓
        Reranker（精排）
                 ↓
         Top-N Context
```

### 1.3 异构得分融合机制与权重调优

* **量纲问题**：Dense 输出余弦相似度或点积，BM25 输出无界统计分，不能直接相加。
* **RRF（Reciprocal Rank Fusion，倒数秩融合）**：
  * *机制*：按各检索通道中的排名融合，不直接比较原始得分。
  * *优势*：不依赖两路得分尺度，适合异构检索。
  * *限制*：丢失原始分数差距；参数和候选深度影响结果。
* **Min-Max 归一化加权**：
  1. 分别把 Dense 与 Sparse 得分缩放到 `[0, 1]`。
  2. 设置语义权重 $\alpha$（$0 \le \alpha \le 1$）。
  3. 计算：

$$Hybrid\_Score = \alpha \cdot Dense\_Score_{norm} + (1 - \alpha) \cdot Sparse\_Score_{norm}$$

**权重起点**：

* **偏语义**（$\alpha = 0.7 \sim 0.8$）：客服问答、自然语言意图、学术概念。
* **偏关键字**（$\alpha = 0.2 \sim 0.3$）：代码、型号、参数、法规编号。
* **调参依据**：用同一 Query 集比较 Recall@K、MRR、NDCG 和延迟，不直接照搬权重。
## 2 两阶段精排重排序

### 2.1 初筛与精排的两阶段架构

* **初筛**：
  * *目标*：从海量 Chunk 中快速获得高召回候选。
  * *机制*：Dense + Sparse 混合检索。
* **精排**：
  * *目标*：在较小候选集上精确判断 Query 与 Document 的相关性。
  * *机制*：Cross-Encoder Reranker。
### 2.2 Bi-Encoder 与 Cross-Encoder 的对比

```text
Bi-Encoder:
Query → Encoder → Vector Q ┐
                           ├→ 点积 / 余弦
Document → Encoder → V D ──┘

Cross-Encoder:
Query + Document → Encoder → 相关性得分
```

* **Bi-Encoder（双编码器）**：
  * *机制*：Query 与 Document 独立编码为向量，用点积或余弦比较。
  * *优势*：Document 向量可离线计算；适合大范围初筛。
  * *限制*：没有 Token 级交叉注意力，局部细节匹配较弱。
  * *定位*：第一阶段召回。
* **Cross-Encoder（交叉编码器）**：
  * *机制*：将 Query 与 Document 拼接后输入模型，执行 Token 级 Cross-Attention。
  * *优势*：更能捕捉细粒度相关性，适合最终排序。
  * *限制*：每个 Query-Document 对都需实时推理，无法低成本全量扫描。
  * *定位*：第二阶段精排。

核心分工可概括为：**Retriever 负责召回得够全，Reranker 负责排序得够准**。

**评估指标**：
* **Recall@K**：正确片段是否进入前 K 个候选集。
* **MRR**：第一个正确结果排在第几位，适合单条最优证据问答。
* **NDCG**：评估多个相关结果的整体排序质量。

## 3 检索后处理与上下文构建

### 3.1 目标与问题

* **目标**：用尽量少的 Token 提供精准、完整且互补的证据。
* **冗余**：多路检索和多查询可能召回大量近似内容。
* **局部相关**：长切片中可能只有少量段落真正回答问题。
* **注意力分散**：无关内容会稀释证据密度并增加成本。

**核心权衡**：相关性、信息覆盖度与 Token 成本不能同时最大化。
### 3.2 上下文处理流水线

```text
Reranker 输出 Top-N
→ 去重与合并
→ 压缩或筛选
→ 上下文重排
→ Token 预算分配
→ 组装 Prompt
→ LLM
```

### 3.3 去重与近重复检测
* **精确去重**：
  * *机制*：使用 MD5、SHA-256 或字符串精确比对。
  * *适用*：完全相同的文本或重复导入。
* **近重复检测**：
  * *机制*：使用语义相似度阈值或局部敏感哈希识别高度重叠内容。
  * *适用*：改写、模板化段落和多版本文档。
  * *限制*：阈值过松会误删有细微差异的关键证据。
### 3.4 上下文压缩

* **Extractive Compression（抽取式压缩）**：
  * *机制*：直接从原文筛选与 Query 相关的句子或段落。
  * *优势*：不重写事实，计算快，幻觉风险低。
  * *限制*：语言连贯性可能下降，跨句信息整合能力弱。
  * *适用*：法律、医疗、金融等事实准确性优先场景。
* **Generative Compression（生成式压缩）**：
  * *机制*：用轻量 LLM 摘要、提炼或重构上下文。
  * *优势*：压缩率高，表达连贯，可跨句融合。
  * *限制*：增加调用延迟和成本，存在信息遗漏或幻觉风险。
  * *适用*：允许语义重组的通用问答与摘要。
### 3.5 上下文重排序与 Token 预算管理
* **Lost in the Middle**：
  * *现象*：长上下文中部信息更容易被模型忽略或混淆。
  * *策略*：把最关键证据放在开头和结尾，次要信息放在中间。
  * *限制*：位置偏差与模型、任务和上下文结构有关，必须通过实际评测验证。
* **Token 预算**：
  * 系统提示词：通常预留 1K～2K Tokens。
  * 对话历史：通常分配 2K～4K Tokens，并按滑动窗口或摘要压缩。
  * 当前问题：通常保留 100～500 Tokens。
  * 检索上下文：使用剩余额度；超出时按重排优先级截断或二次压缩。

**工程要求**：预算必须从模型上下文上限反推，不能固定使用一套数值。
### 3.6 结构化切片后处理范式

* **Sentence Window**：
  * *机制*：中心句建向量，前后 N 句存入 Metadata；命中后扩展为窗口。
  * *目标*：细粒度匹配 + 局部上下文恢复。
* **Parent-Child Retrieval**：
  * *机制*：Child 负责向量匹配，Parent 从 KV 存储按 `parent_id` 取回。
  * *典型粒度*：Child 200～400 Tokens，Parent 1000～2000 Tokens。
  * *目标*：小块召回准，大块生成全。

切块方式详见 [[02_文本分块策略]]。
### 3.7 上下文质量评估指标

* **Context Recall**：回答问题所需的关键事实是否完整进入上下文。
* **Context Precision**：上下文中相关信息所占比例及排序位置。
* **Noise Sensitivity**：存在无关切片时模型产生错误回答的频率；越低越好。

## 4 生成层：从上下文到答案

### 4.1 答案生成的三要素与约束

* **Context**：提供事实依据。
* **System Prompt**：定义角色、格式、引用规则和拒答条件。
* **用户 Query**：明确回答目标与范围。

**核心约束**：模型只能在 Context 能支撑的范围内回答；证据不足时明确拒答或请求补充。
### 4.2 有据生成、引用溯源与质量评估

* **Grounded Generation（有据生成）**：
  * *机制*：要求结论对应 Context 中的证据。
  * *边界*：Prompt 约束不能保证零幻觉，仍需引用校验和质量评测。
* **Citation（引用溯源）**：
  * *机制*：把结论绑定到文档、章节、页码或 Chunk ID。
  * *作用*：支持人工核查、错误定位和权限审计。

**生成评测**：

* **Faithfulness**：答案是否有 Context 支撑。
* **Answer Accuracy**：答案是否正确。
* **Hallucination**：是否生成 Context 不存在或与事实冲突的内容。
* **Citation Accuracy**：引用是否能支持对应结论。

评测方法可进一步参考 [[_自动化评测]]。
## 5 检索链路定位

### 5.1 在线处理全景

离线数据构建见 [[00_RAG总览]]。本阶段处理在线检索与生成：

```text
04 查询工程
→ Dense + Sparse 并行召回
→ RRF / 归一化加权融合
→ Cross-Encoder Reranker
→ 去重、扩展、压缩和 Token 预算
→ LLM 有据生成
→ 引用溯源与评测
```

### 5.2 工程取舍

* **召回优先**：正确证据不在候选集，Reranker 和 Prompt 都无法补救。
* **精排补精度**：候选多时先用便宜检索初筛，再让 Cross-Encoder 处理少量候选。
* **上下文提纯**：去重、压缩和 Token 预算同时影响答案质量、成本与延迟。
* **分层评测**：召回、重排、上下文和生成必须分别定位问题。
* **最简链路**：没有评测证据时，不同时增加混合检索、多查询、重排和上下文压缩。
