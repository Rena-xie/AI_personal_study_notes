### 2.4 向量数据库与索引

* **Vector Database（向量数据库）**：用于存储、索引和检索高维向量，支持百万级向量的毫秒级相似度搜索，并通常同时保存向量、Chunk 原文与 Metadata 的数据库或检索系统。
* **ANN（Approximate Nearest Neighbor，近似最近邻）**：通过近似搜索减少计算量，以较小的召回损失换取更低延迟和更高吞吐。
* **Nearest Neighbor（最近邻）**：向量空间中与 Query Vector 最接近的向量。
* **HNSW（Hierarchical Navigable Small World，分层可导航小世界）**：一种常见的 ANN 图索引算法，通过多层邻居关系加速近似最近邻搜索。
* **Top-K**：从检索结果中选取得分最高的前 K 个结果。
* **Index（索引）**：用于加快数据查找的结构；在 RAG 中可以包括向量索引和关键词倒排索引。
### 2.5 查询工程 Query Engineering

* **Query Rewrite（查询重写）**：在保持原始意图的前提下，将用户 Query 改写成更加完整、明确、适合检索的表达。
* **Query Expansion（查询扩展）**：为 Query 增加关键词、同义词、相关术语或其他检索表达，以扩大匹配范围。
* **Multi-Query（多查询）**：从一个用户问题生成多个不同检索视角的 Query，并分别检索后进行结果合并。
* **Query Routing（查询路由）**：根据 Query 的类型、意图和复杂度，决定应该采用哪一种检索路径。
* **Query Router（查询路由器）**：执行 Query Routing 的规则、模型或组件。
* **Step-back Prompting（退一步提示）**：先将具体问题抽象成更高层次的原理问题，检索基础知识后再解决具体问题。
* **HyDE（Hypothetical Document Embeddings，假设性文档嵌入）**：先让 LLM 生成一个与问题相关的假设性文档，再将其向量化，用假设文档向量去检索真实知识。
* **Hypothetical Document（假设性文档）**：HyDE 中由 LLM 生成、用于辅助检索的假设答案或文档。
* **Query-to-Document Matching（查询到文档匹配）**：直接将用户 Query 与知识库 Document / Chunk 进行匹配。
* **Document-to-Document Matching（文档到文档匹配）**：HyDE 等方法中，通过一个假设性文档去匹配真实知识文档。

### 2.6 检索 Retrieval

* **Retrieval（检索）**：从知识库中寻找与 Query 相关内容的过程。
* **Retriever（检索器）**：负责执行 Retrieval 的组件。
* **Dense Retrieval（稠密检索）**：通过 Embedding Vector 和相似度计算进行语义检索，擅长处理语义相近但词面不同的表达。
* **Sparse Retrieval（稀疏检索）**：基于词项匹配、词频、逆文档频率和倒排索引进行检索，擅长处理精确关键词、编号和专有名词，典型代表为 BM25 与 TF-IDF。
* **Lexical Retrieval（词法检索）**：根据文本词项本身进行匹配的检索方式。
* **Semantic Retrieval（语义检索）**：根据文本语义表示进行匹配的检索方式。
* **Keyword Search（关键词检索）**：根据 Query 中的关键词在文档中进行匹配。
* **BM25（Best Matching 25）**：经典的 Sparse Retrieval 算法，主要综合 Term Frequency、Inverse Document Frequency 和文档长度归一化进行相关性评分。
* **TF（Term Frequency，词频）**：某个 Query 词在文档中出现的频率。
* **IDF（Inverse Document Frequency，逆文档频率）**：衡量一个词在整个文档集合中的稀有程度，越稀有通常越具有区分能力。
* **Term Frequency Saturation（词频饱和）**：BM25 中词频增加带来的收益逐渐递减，而不是无限线性增加。
* **Document Length Normalization（文档长度归一化）**：降低长文档因包含更多词而产生的不公平优势。
* **Hybrid Retrieval（混合检索）**：结合 Dense Retrieval 与 Sparse Retrieval 的双路检索方式，同时利用语义匹配和精确词法匹配能力。

### 2.7 融合 Fusion 与重排序 Reranking

* **Fusion（融合）**：将多个 Retriever 的检索结果合并成统一候选集的过程。
* **Score Fusion（分数融合）**：对不同 Retriever 的分数进行归一化或加权后融合。
* **Rank Fusion（排名融合）**：根据不同 Retriever 的排名位置进行结果融合。
* **RRF（Reciprocal Rank Fusion，倒数排名融合）**：一种常见的 Rank Fusion 方法，不直接比较 Dense 和 BM25 的原始分数，而根据结果在各路检索中的排名计算融合得分。
* **Candidate Set（候选集）**：经过初步 Retrieval / Fusion 后，交给后续 Reranker 进行精筛的候选结果集合。
* **Reranking（重排序）**：对初步召回的候选结果进行更精细的相关性判断，并重新排序。
* **Reranker（重排序器）**：负责 Reranking 的模型或组件。
* **Cross-Encoder（交叉编码器）**：同时输入 Query 和 Document / Chunk，对二者关系进行联合建模，常用于高精度 Reranking。
* **Relevance（相关性）**：Query 与候选 Chunk 在当前任务中的相关程度。
* **Relevance Score（相关性分数）**：Reranker 或其他检索器对候选结果给出的相关性评分。

### 2.8 Context 与 LLM 生成

* **Context（上下文）**：提供给 LLM 的额外信息，包括用户问题、检索结果、历史对话等。
* **Context Construction（上下文构建）**：从 Retrieval / Reranking 结果中选择、排序、组织最终提供给 LLM 的信息。
* **Context Selection（上下文选择）**：从大量候选 Chunk 中选取真正需要送给 LLM 的内容。
* **Context Window（上下文窗口）**：LLM 单次能够处理的上下文 Token 范围。
* **Evidence（证据）**：支持最终答案的检索内容。
* **Grounding（知识依据/有据生成）**：让 LLM 的回答建立在外部知识或检索证据之上，而不是完全依赖模型参数。
* **Generation（生成）**：LLM 根据 Query、Context 和 Prompt 生成最终答案的过程。
* **LLM（Large Language Model，大语言模型）**：负责理解上下文并生成自然语言回答的模型。
* **Temperature（温度）**：控制生成模型采样随机性的参数，不是 RAG 每个步骤都存在的通用参数。
* **Hallucination（幻觉）**：模型生成与事实、证据或知识库不一致的内容。
* **Faithfulness（忠实性）**：答案是否忠实于提供给模型的 Context / Evidence，有无凭空捏造事实。
* **Answer Correctness（答案正确性）**：最终回答与标准答案或真实事实的一致程度。
* **Answer Relevance（答案相关性）**：最终答案是否真正回应了用户问题。

### 2.9 检索评测 Retrieval Evaluation

* **Evaluation（评测）**：通过测试数据和指标衡量 RAG 各环节质量的过程。
* **Evaluation Dataset（评测数据集）**：用于评估系统效果的 Query、标准答案、相关文档等数据集合。
* **Golden Dataset（黄金数据集/标准数据集）**：经过人工确认、具有可靠 Ground Truth（标准答案/相关文档）的评测集合。
* **Ground Truth（真实答案/标准结果）**：用于判断系统结果是否正确的参考标准。
* **Benchmark（基准测试）**：用于比较不同模型、策略或系统性能的标准测试体系。
* **Baseline（基线）**：用于与优化方案进行对比的基础实现。
* **Recall（召回率）**：所有应该找到的相关结果中，系统实际找到的比例。
* **Recall@K（前 K 召回率）**：前 K 个检索结果中包含相关知识的能力，回答“应该找到的知识有没有被召回”。
* **Precision（查准率）**：检索结果中真正相关结果所占的比例。
* **Precision@K（前 K 查准率）**：Top-K 检索结果中真正相关结果的比例。
* **MRR（Mean Reciprocal Rank，平均倒数排名）**：关注第一个相关结果出现得有多靠前。
* **NDCG（Normalized Discounted Cumulative Gain，归一化折损累计增益）**：综合考虑结果相关程度和排名位置，评价排序质量。
* **Context Recall（上下文召回率）**：回答所需要的关键信息是否被检索到并进入 Context。
* **Context Precision（上下文查准率）**：提供给 LLM 的 Context 中，有多少内容是真正相关、有用的；高相关片段是否排在最前面、噪声片段占比是否足够低。
* **Regression（回归/效果退化）**：代码或配置更新后，原有 RAG 指标出现下降。
* **A/B Test（A/B 测试）**：在相同评测条件下比较两个方案效果。

### 2.10 系统编排与 Agent

* **Pipeline（流水线）**：按照固定顺序连接多个数据处理或检索步骤形成的执行链。
* **Workflow（工作流）**：多个步骤、条件和分支组成的业务执行流程。
* **Orchestration（系统编排）**：负责组织、调度和协调多个模型、工具、Retriever、Reranker 等组件。
* **Tool（工具）**：Agent 可以调用的外部能力，如搜索、数据库、API、代码执行等。
* **Tool Calling（工具调用）**：由 LLM 判断需要使用某个工具并生成工具调用参数，再由程序实际执行。
* **Function Calling（函数调用）**：通过结构化函数参数让模型调用后端函数。
* **Agent（智能体）**：能够根据目标自主进行判断、调用工具、执行步骤并根据结果继续行动的系统。
* **Agentic RAG（Agent 式 RAG）**：由 Agent 动态决定检索、查询、工具调用和后续行动的 RAG 架构。
* **Routing（路由）**：根据 Query、任务类型或中间结果决定系统应该走哪条处理路径。
* **State（状态）**：Workflow / Agent 执行过程中持续保存的上下文与中间结果。
* **State Machine（状态机）**：用状态和状态转换描述系统执行逻辑。
* **Parallel Execution（并行执行）**：多个 Query、Retriever 或工具同时执行。
* **Sequential Execution（串行执行）**：多个步骤按照固定顺序依次执行。
* **Fallback（降级/备用路径）**：主要策略失败或质量不足时切换到备用策略。

### 2.11 可观测性与调试 Debugging

* **Observability（可观测性）**：通过 Logs、Metrics、Traces 等手段理解系统内部运行状态。
* **Monitoring（监控）**：持续观察系统的性能、错误和资源使用情况。
* **Logging（日志）**：记录系统执行过程中的事件、输入、输出、错误和关键状态。
* **Tracing（链路追踪）**：追踪一次 Query 从进入系统到最终回答经过的完整处理链路。
* **Trace（追踪链路）**：一次请求完整的执行记录。
* **Span（链路跨度）**：Trace 中代表某个具体步骤的执行单元，如 Query Rewrite、Retrieval、Rerank、LLM。
* **Metrics（指标）**：用于量化系统运行状态的数值，例如 Latency、Recall、Error Rate。
* **Latency（延迟）**：系统从请求开始到结果返回所花费的时间。
* **Throughput（吞吐量）**：单位时间内系统能够处理的请求量。
* **Error Rate（错误率）**：请求执行失败的比例。
* **Token Usage（Token 使用量）**：LLM 输入和输出所消耗的 Token 数量。
* **Cost（成本）**：API、计算、存储和网络等资源带来的运行成本。
* **Debugging（调试）**：定位和修复系统质量、逻辑或运行问题的过程。
* **Root Cause Analysis（根因分析）**：从最终错误结果逐层向前定位真正导致问题的环节。

### 2.12 安全与运维

* **Security（安全）**：保护知识库、模型、数据和系统免受未授权访问或恶意操作。
* **Authentication（身份认证）**：确认“你是谁”。
* **Authorization（授权）**：确认“你可以访问什么”。
* **Access Control（访问控制）**：根据身份和权限限制数据或功能访问。
* **Permission（权限）**：用户或角色允许执行的操作范围。
* **Data Isolation（数据隔离）**：避免不同用户、部门或租户之间的数据互相泄露。
* **Multi-tenancy（多租户）**：同一套系统服务多个彼此隔离的用户或组织。
* **PII（Personally Identifiable Information，个人可识别信息）**：可用于识别个人身份的信息。
* **Data Privacy（数据隐私）**：保护用户和企业数据不被未授权使用或泄露。
