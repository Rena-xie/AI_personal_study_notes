## 1 核心概念与生成机制

### 1.1 大模型的本质

* **生成方式**：模型基于已有上下文预测下一个 Token 的概率分布，采样出一个 Token 后追加到上下文，再继续预测，直到命中结束条件。
* **直接结果**：模型不是从数据库中查找固定答案；相同输入可能得到不同输出，表达流畅也不代表事实正确。
### 1.2 核心术语

* **Token（词元）**：模型处理文本的基本单位，可能对应完整单词、词的一部分、标点或字节片段。
* **Context Window（上下文窗口）**：单次请求可处理的 Token 总量上限，通常同时计入输入与输出。
* **Prompt（提示词）**：提供给模型的任务描述、上下文、约束和输出要求。
* **System Prompt（系统提示词）**：优先级通常高于普通用户指令的配置层，用于定义角色、工作原则、回答风格和工具规则。

**关键边界**：
* 上下文窗口更大，不表示模型能同等有效地利用全部内容。
* System Prompt 适合表达行为约定，不能代替应用层的权限校验和安全隔离。

## 2 生成参数与输出控制

### 2.1 控制随机性与多样性

* **Temperature（温度）**：
  * *机制*：调整候选 Token 概率分布的平滑程度。
  * *表现*：数值较低时，高概率 Token 更容易被选中；数值较高时，低概率 Token 获得更多机会，输出更发散。
  * *限制*：数值过高会放大不稳定和无意义内容；设为 0 通常更稳定，也不应假定所有服务都能保证完全确定。
* **Top-p（核采样）**：
  * *机制*：将候选 Token 按概率从高到低排列，只在累积概率达到阈值 `p` 的最小集合中采样。
  * *表现*：较低的 `p` 截掉更多长尾候选，较高的 `p` 保留更多多样性。
  * *限制*：阈值过低会压缩表达空间，过高则接近正常概率采样。

**组合使用**：

* Temperature 与 Top-p 不是严格的“二选一”关系。
* 工程中通常固定一个参数，只调整另一个，再用固定测试集验证稳定性。

### 2.2 控制长度与终止位置

* **Max Output Tokens（最大输出 Token 数）**：
  * *机制*：限制本次响应最多生成多少 Token。
  * *表现*：直接限制输出长度、延迟和费用上限。
  * *限制*：不能防止幻觉，也不能保证答案完整；可能截断结构化结果。
* **Stop Sequences（停止序列）**：
  * *机制*：指定一个或多个字符串，生成内容首次匹配时终止输出。
  * *表现*：适合分隔结构化结果或阻止继续生成。
  * *限制*：合法内容可能意外触发停止；停止片段通常不会进入最终结果。

### 2.3 抑制重复与鼓励新内容

* **Frequency Penalty（频率惩罚）**：
  * *机制*：Token 在已有文本中出现次数越多，后续受到的惩罚越大。
  * *表现*：抑制单词、短语或局部结构的机械重复。
* **Presence Penalty（存在惩罚）**：
  * *机制*：Token 只要出现过就受到惩罚，不随出现次数累加。
  * *表现*：鼓励模型引入新词汇或新主题。

**共同限制**：

* 参数过高会破坏专有名词、代码标识、固定格式和上下文连贯性。
* 两个参数只改变 Token 选择倾向，不能保证文本在语义层面真正多样。

## 3 提示词工程

### 3.1 基础提示范式

* **Zero-Shot（零样本提示）**：
  * *机制*：只给任务指令和必要上下文，不提供示例。
  * *表现*：输入短、调用成本低，适合任务明确且模型已有相关能力的场景。
  * *限制*：输出格式和判断标准较难保持稳定。
* **Few-Shot（少样本提示）**：
  * *机制*：增加 1 个或多个“输入 → 输出”示例。
  * *表现*：固定输出结构、风格或判断标准。
  * *限制*：示例占用 Token；错误或偏差示例会被模型放大。

### 3.2 推理增强方法

* **CoT（思维链提示）**：
  * *机制*：通过示例或指令引导模型先拆解中间步骤，再给出答案。
  * *表现*：提升多步计算、推演和逻辑任务的稳定性。
  * *限制*：增加 Token、延迟和成本；模型写出的推理过程不一定忠实反映其真实计算过程，不能直接当作正确性证明。
* **Auto-CoT（自动思维链）**：
  * *机制*：先对问题聚类，从各簇抽取代表问题；再用 Zero-Shot CoT 自动生成推理链，并按长度、重复、格式等规则过滤。
  * *表现*：减少人工编写 Few-Shot 推理步骤的成本。
  * *限制*：自动生成的推理链仍需抽样验证；“5 步左右”不是通用规则。
* **ToT（思维树）**：
  * *机制*：将解空间组织为多个思考节点；模型生成候选状态、评价状态，再通过搜索、剪枝和回溯选择路径。
  * *表现*：允许同时探索多种方案，适合需要比较路径或修正死路的问题。
  * *限制*：模型调用次数和计算成本显著上升。
* **Active-Prompt（主动提示）**：
  * *机制*：同一批问题多次采样，以结果或推理的不一致性估计不确定性；选出高不确定性题目交给人工编写 CoT，再作为高质量示例使用。
  * *表现*：把人工标注预算集中到最容易出错的题目。
  * *限制*：需要多次运行和人工投入；筛选出的题目不一定覆盖真实业务分布。

### 3.3 任务分解与工具辅助

* **Prompt Chaining（提示链）**：
  * *机制*：用代码将上一个模型节点的输出传给下一个节点，分步转换或处理。
  * *示例*：提示一提取文档引文 → 提示二结合引文回答问题。
  * *限制*：单步错误会向后传播，并增加调用成本和端到端延迟。
* **PAL（程序辅助语言模型）**：
  * *机制*：模型把自然语言问题转换为程序，由外部解释器执行计算，再将结果回填到答案中。
  * *表现*：降低算术、日期和统计等硬计算错误。
  * *限制*：问题理解、程序逻辑和数据仍可能出错，不能实现“0 计算错误”；执行代码必须设置权限、超时和隔离环境。
* **DSP（方向刺激提示）**：
  * *机制*：训练一个轻量模型，根据输入生成引导线索；大模型参数保持不变，小模型依据回答评分继续优化。
  * *表现*：无需微调大模型，也能更稳定地约束答案内容或风格。
  * *限制*：效果依赖评价器；评分标准设计不当会让模型只迎合分数。

工具调用和权限边界可参见 [[02_工具调用]]。

### 3.4 自动提示优化

* **APE（自动提示工程师）**：
  * *机制*：自动生成候选提示，在开发集上执行和评分，再选择或迭代表现更好的提示。
  * *表现*：降低重复调参成本，适合提示版本多、人工比较成本高的场景。
  * *限制*：可能过拟合开发集，最终必须用独立验证集检查。
### 3.5 方法选择

* **任务明确、格式稳定**：优先 Zero-Shot 或 Few-Shot。
* **多阶段处理**：使用 Prompt Chaining，在关键节点校验中间结果。
* **多步推演**：比较 CoT 与普通提示的准确率、延迟和 Token 成本。
* **精确算术或确定性流程**：优先调用工具或执行程序，不要只靠自然语言推理。
* **存在高价值错题、人工预算有限**：使用 Active-Prompt 定向补充推理示例。
* **需要探索多条解法**：再考虑 ToT，并评估调用成本。
* **提示结构复杂、需要动态组装**：进一步参考 [[04_上下文工程]]。
