### 1. 核心概念与学术术语体系
* **大模型的本质**：模型并不是直接输出一整段固定的文本，而是基于输入的上下文，去预测并输出下一个 Token（词元）的概率分布。
* **核心学术术语**：
  * **Token（词元）**：大模型处理文本的基本单位。
  * **上下文窗口**：大模型单次交互中能够接收并处理的最大 Token 限制。
  * **Prompt（提示词）**：引导大模型输出的文本指令。
  * **System Prompt（系统提示词）**：定义 Agent 的系统设定，包括角色设定、人格属性、专业领域视角、权限限制与安全防御边界等。

### 2. 参数设置与生成控制

#### 控制结果的确定性与创造性
* **Temperature（温度）**：
  * *机制*：调整全局概率分布的平滑度。
  * *表现*：数值越小，输出结果越确定，偏向选择概率最高的词元；数值越大，输出越随机，概率低的词元也有机会被选中。
* **Top_p（核采样）**：
  * *机制*：仅在累积概率达到 $p$ 的高概率词元集合中进行采样，直接截断长尾词。
  * *表现*：用于精细控制生成多样性，常与 Temperature 二选一进行调节。

#### 控制结果的长度与结构（工程控本）
* **Max Length（最大长度）**：
  * *机制*：强制限制生成的最大 Token 数。
  * *表现*：直接卡死成本上限，防止大模型发生幻觉或由于指令不清生成过长内容。
* **Stop Sequences（停止序列）**：
  * *机制*：在 API 层面指定一串特殊字符。
  * *表现*：一旦模型生成的 Token 匹配到该字符，立即强行终止生成，用于精准控制结构化输出。

#### 减少重复与鼓励多样化
* **Frequency Penalty（频率惩罚）**：
  * *机制*：根据词元在已有文本中出现的绝对频次（次数）施加惩罚。
  * *表现*：专门针对下一个生成词元，减少单词的机械、循环重复。
* **Presence Penalty（存在惩罚）**：
  * *机制*：只要该词元在已有文本中出现过即施加惩罚，不累加计算出现次数。
  * *表现*：鼓励文本在题材和词汇上产生多样化，防止模型高频重复同一主题或用词。

### 3. 全球主流大模型对比分析

#### 第一梯队：顶尖闭源模型
* **Anthropic Claude 系列**：
  * **Fable 5 / Mythos 5**：能力天花板，擅长复杂推理、长程 Agent、硬核编程（SWE-bench 类）。价格较高，安全限制及拒答偏多。
  * **Opus 5**：高性价比旗舰模型，能力接近顶部，Agent 和写作表现稳定，为当前主力旗舰。
* **OpenAI GPT-5.6 系列**：
  * **Sol**：旗舰模型，编程与工具调用能力突出，生态完备（Codex 与各类插件）。
  * **Terra / Luna**：中低档模型，Luna 成本极低，适合大规模量产部署。
* **xAI Grok 4.5**：
  * 性能位于 GPT-5.6 Sol 与 Opus 5 之间，核心优势在于实时信息检索（特别是 X 平台数据）和较少的审查，上下文窗口为 500K。

#### 第二梯队：国产崛起与开源阵营
* **月之暗面 Kimi K3**：开源权重强者，长上下文与推理能力均衡。
* **阿里 Qwen3.8 Max**：中文能力、工具链与生态完善，综合表现跻身全球前列。
* **DeepSeek V4 系列 (尤其 Flash)**：性价比极高，低成本实现优秀的推理与代码能力。
* **智谱 GLM-5.2**：开源阵营优秀代表，在特定垂直任务表现亮眼。
* **Google Gemini 3.x**：多模态与超长上下文保持优势，纯文本推理有所掉队，Flash 系列具备速度与成本优势。
* **Meta Muse Spark**：开源阵营黑马

#### 多模型协同策略总结
现代应用已进入多模型混用阶段：
1. **追求极致能力**：选择 Claude Fable / Opus 5
2. **注重生态与全能**：选择 GPT-5.6 Sol
3. **注重性价比与实时信息**：选择 Grok 4.5 或 DeepSeek
4. **国产可控与开源需求**：选择 Kimi K3 或 Qwen3.8 Max

常见组合分工为：Claude 撰写代码与长文，Grok 负责实时检索，DeepSeek 处理批量任务，Qwen/Kimi 处理中文本地化需求。
