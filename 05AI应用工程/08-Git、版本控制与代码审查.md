## 1 Git基础概念与工作流

### 1.1 核心状态与命令
在 Git 版本控制中，代码变更通常经历工作区、暂存区和本地仓库三个状态。掌握以下核心命令可实现对代码状态与变更的精准管理。

*  查看状态：`git status`，用于检查当前工作区与暂存区的状态，确认哪些文件被修改、已暂存或未跟踪。
*  暂存变更：`git add <文件>`，将指定文件的修改加入暂存区，准备提交。
*  创建提交：`git commit`，将暂存区中的变更永久保存到本地仓库，生成一次本地提交。
*  查看提交历史：
   *  `git log`：查看完整的提交历史。
   *  `git log --oneline`：用简洁的单行格式查看提交历史。
*  查看具体提交与变更：
   *  `git show HEAD`：查看最近一次提交的详细内容与变更。
   *  `git show <commit>`：查看指定提交的信息与变更。
   *  `git diff`：查看工作区相对于暂存区未暂存的修改。
   *  `git diff --staged`：查看暂存区相对于当前提交准备提交的修改。
   *  `git diff HEAD`：比较当前工作区与最近一次提交的差异，包含已暂存和未暂存的跟踪文件修改。

### 1.2 提交说明书写规范
良好的提交说明能显著提升项目可维护性与审查效率。

*  推荐格式：动词 + 具体对象 + 变更目的

## 2 分支管理与多Agent并行开发

### 2.1 分支核心概念
分支是 Git 实现隔离开发与并行探索的基础机制。

| **概念** | **含义** |
| ------ | ------ |
| main | 通常用于保存主开发线的分支 |
| branch | 一条独立的开发历史 |
| HEAD | 通常指向当前检出的分支或提交 |
| checkout / switch | 切换分支或检出版本 |
| merge | 将另一条分支的变更整合进当前分支 |
| merge conflict | 合并冲突，需要人工判断如何整合 |

### 2.2 分支操作与Git Worktree机制
*  切换与创建分支：
   *  `git switch -c feature/web-fetch`：创建 `feature/web-fetch` 分支并立即切换到该分支。
   *  `git switch main`：切换回主分支。
*  多 Agent 并行机制：
   *  分支不等于独立的工作区。若需要让两个 Agent 真正并行工作，可以考虑使用 Git Worktree（工作树）。
   *  Git Worktree 允许同一个 Git 仓库在不同目录中同时检出不同分支，从而避免频繁切换分支干扰执行环境。

## 3 Diff版本对比与代码审查

### 3.1 Diff基本原理
Diff 是对比两个版本之间差异的结果，明确标示出哪些内容被新增、删除或修改。

### 3.2 针对不同场景的对比命令
*  `git diff`：检查工作区相对于暂存区的未暂存修改。
*  `git diff --staged`：检查暂存区相对于当前提交准备提交的修改。
*  `git diff HEAD`：检查当前工作区和暂存区中的跟踪文件相对于当前提交的整体差异。
*  `git show <commit-id>`：检查指定提交的具体变更内容。

## 4 代码撤销与历史恢复机制

### 4.1 不同阶段的撤销策略
当代码出现错误或需要调整时，需根据修改所处阶段选择合适的撤销命令：

*  未暂存修改丢弃：修改尚未提交，只想丢弃单个文件的未暂存修改时，使用 `git restore`。
*  已暂存撤回：修改已暂存但暂时不想提交时，使用 `git restore --staged`。
*  本地提交调整：本地最近一次提交有问题，想保留修改再调整时，使用 `git reset --soft` 或 `git reset --mixed`，按需要选择。
*  已共享提交撤销：已推送到共享分支的提交有问题时，使用 `git revert`。
*  彻底丢弃修改：需要彻底丢弃指定范围的本地修改时，应先备份并核实，再考虑使用 `git reset --hard`。

### 4.2 找回丢失提交
*  `git reflog`：用于找回移动过的提交位置。当误删除分支或误执行重置操作时，可以通过查看终端历史记录指针的移动轨迹找回原来的提交。

## 5 远程协作与同步机制

### 5.1 远程交互命令
*  `git clone`：将远程仓库克隆到本地。
*  `git fetch`：获取远程分支和提交信息，更新本地的远程追踪快照。
*  `git pull`：获取远程更新并整合到当前分支。
*  `git push`：将本地提交推送到远程仓库。

### 5.2 本地分支与远程追踪分支
*  `main`：你本地的主分支。
*  `origin/main`：你本地记录的、远程仓库 origin 的 main 分支状态。

## 6 冲突解决与分支整合策略

### 6.1 合并冲突识别与标记解析
当合并两条分支出现冲突时，冲突文件中会显示特定的结构标记：

```
<<<<<<< HEAD
timeout = 20
=======
timeout = 30
>>>>>>> origin/main
```

标记含义说明：
*  `<<<<<<< HEAD`：当前分支一侧的内容。
*  `=======`：分隔双方的修改。
*  `>>>>>>> origin/main`：另一侧的内容。

人工判断并保留正确代码后，删除标记符号即可完成冲突解决。

### 6.2 Merge与Rebase整合方式对比
*  Merge（合并）：将另一条分支整合进当前分支。若双方历史已经分叉，通常会产生一个合并提交。
*  Rebase（变基）：将当前分支的提交重新应用到另一个基准提交之上，形成新的提交历史。

## 7 易混淆与高风险命令剖析

### 7.1 Revert、Reset、Rebase与Force Push对比
针对常见易混淆和风险命令的作用原理如下：

*  `git revert`：新增一个反向提交，通常更适合撤销已共享的错误提交。
*  `git reset`：移动当前分支指针，并根据参数改变暂存区或工作区状态。
*  `git rebase`：重新应用提交，可能生成新的提交 ID。
*  `git push --force`：允许推送时覆盖远程分支引用，可能影响他人的历史。
