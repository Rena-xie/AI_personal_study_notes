### 1.2 评估驱动开发的三大核心原则
1. **建立量化基线**：在进行任何配置微调、提示词改写或架构重构前，先用标准测试集跑出当前系统的性能基线分数。
2. **两阶段解耦拆控评估**：把 RAG 解耦为检索召回阶段与生成回答阶段，分别测量检索召回率与生成忠实度，精准定位性能瓶颈。
3. **数据驱动迭代**：每一次代码变更、参数调整或提示词更新，都必须重新运行自动化评估脚本，严格根据各项指标的涨跌决定是否上线发布。



#### 4.1.7 指标速查表

| 指标 | 中文名 | 核心问题 |
| ------------------ | ------ | ------------------ |
| Recall@K | 前 K 召回率 | 该找到的知识有没有找到？ |
| Precision@K | 前 K 查准率 | 找到的东西有多少是真相关？ |
| MRR | 平均倒数排名 | 第一个正确结果排得够不够靠前？ |
| NDCG | 归一化折损累计增益 | 多个结果的相关程度和排序是否合理？ |
| Answer Correctness | 答案正确性 | 最终答案对不对？ |
| Faithfulness | 忠实度 | 答案有没有忠实依据上下文？ |
| Context Recall | 上下文召回率 | 答案所需信息有没有被取回来？ |
| Context Precision | 上下文查准率 | 上下文中有多少是有用的？ |

#### 4.3.4 评测方法对比与融合策略
| 评估范式 | 核心代表 | 优势 | 局限 | 工程落地定位 |
| ------ | ------ | ------ | ------ | ------ |
| **语义裁判** | Ragas / TruLens / GPT-4o | 具备深层语义与逻辑理解能力，打分与人类主观体验高度一致 | API 成本较高、评估速度慢，可能存在模型偏见 | 用于精细化打分、最终质量把关与复杂推理校验 |
| **经典词汇匹配** | ROUGE / BLEU / METEOR | 确定性强、毫秒级响应、0 成本，客观透明 | 无法理解同义词与意图重构，对语义相同但表达不同的回答误判率高 | 用于 CI/CD 快速批量初筛、字面一致性回归测试 |

### 5.4 A/B 测试

离线指标涨了，不等于线上体验变好。A/B 测试的做法是：把流量随机分成两组，一组跑旧方案、一组跑新方案，在相同时间窗口内对比业务指标（采纳率、引用点击率、追问率等）。

随机分组与"只变一个变量"是它成立的前提。RAG 场景中常用的线上指标包括答案采纳率、引用点击率与负反馈率。

### 5.5 回归测试与 CI/CD

回归测试回答的是“新版本有没有把旧能力弄坏”：

* **固化测试集**：把线上坏例与人工确认过的边界样本沉淀成回归集，随版本一起演进。
* **接进流水线**：把评估脚本挂到 CI 上，每次改动自动跑一遍，指标跌破门槛就阻断合并。
* **守住门槛**：门槛可以设成“核心样本零失败 + 综合指标不退化”，而不是单纯追求分数上涨。

## 6 评估工具链与运维落地

### 6.1 主流评估框架选型
* **Ragas**：专门针对 RAG 系统的开源评估框架，基于 LLM-as-a-Judge 机制自动打分，支持与 LangChain、LlamaIndex 深度集成。
* **DeepEval / TruLens**：支持以 Pytest 单元测试形式将评估规则融入 CI/CD 流程，对 RAG 各流转节点自动运行测试。
* **LangSmith**：LangChain 官方运维评测平台，提供可视化的数据集运行监控与打分跑分功能。
* **DSPy（斯坦福开源）**：前沿提示词编译器，通过算法结合自动化评估测试集，在后台全自动调整、编译 System Prompt 并智能更新检索权重，摆脱人工调优模式。

### 6.2 自建 Python 评估执行器示例
通过自建评估执行代码与 pytest 框架结合，针对不同检索策略自动批量运行黄金测试集并输出结构化对比报告：

```python
import pytest
from typing import Any, Dict, List, Tuple

class RetrievalEvaluationRunner:
    def __init__(self, retrieval_service):
        self.service = retrieval_service

    async def run(self, dataset: List[Dict[str, Any]], strategies: Tuple[str, ...], top_k: int = 5) -> Dict[str, Any]:
        results = {}
        for strategy in strategies:
            total_recall = 0.0
            total_precision = 0.0
            for sample in dataset:
                query = sample["question"]
                target_ids = set(sample["expected_chunk_ids"])

                # 执行指定策略检索
                retrieved_chunks = await self.service.retrieve(query, strategy=strategy, top_k=top_k)
                retrieved_ids = [c.id for c in retrieved_chunks]

                # 计算检索指标
                hits = len(set(retrieved_ids) & target_ids)
                recall = hits / len(target_ids) if target_ids else 0.0
                precision = hits / top_k

                total_recall += recall
                total_precision += precision

            results[strategy] = {
                "Recall@K": round(total_recall / len(dataset), 4),
                "Precision@K": round(total_precision / len(dataset), 4)
            }
        return results

# Pytest 自动化测试集成
@pytest.mark.asyncio
async def test_rag_retrieval_performance(retrieval_service, golden_dataset):
    runner = RetrievalEvaluationRunner(retrieval_service)
    report = await runner.run(
        dataset=golden_dataset,
        strategies=("dense", "sparse", "hybrid"),
        top_k=5
    )
    # 断言混合检索效果必须优于单路纯向量
    assert report["hybrid"]["Recall@K"] > report["dense"]["Recall@K"]
```
